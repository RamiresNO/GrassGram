# Коло — простір для розмов (Python)

Вебмесенджер для навчальних груп. Це повна переробка TypeScript-проєкту на Python:
сервер обробляє запити та зберігає користувачів, розмови й повідомлення, а адаптивний
сайт у браузері працює з ним через той самий REST API.

Бекенд написано **лише на стандартній бібліотеці Python** — ставити залежності не потрібно.

## Можливості

- Створення профілів і перемикання між ними.
- Особисті та групові розмови.
- Історія повідомлень із часовими мітками та автоматичним оновленням.
- Пошук повідомлень у розмовах поточного профілю.
- Перевірка імен користувачів, учасників розмов і тексту повідомлень.
- Адаптивний інтерфейс для комп’ютера, планшета та телефона.

## Запуск

Потрібен Python 3.10+ (перевірено на 3.12).

```sh
python3 -m messenger
```

Відкрий [http://localhost:3000](http://localhost:3000). За замовчуванням дані
зберігаються у `data/messages.json`.

### Налаштування (змінні середовища)

| Змінна           | За замовчуванням         | Опис                                   |
| ---------------- | ------------------------ | -------------------------------------- |
| `HOST`           | `127.0.0.1`              | Адреса, на якій слухає сервер          |
| `PORT`           | `3000`                   | Порт                                   |
| `STORAGE`        | `json`                   | Сховище: `json` або `sqlite`           |
| `DATA_FILE_PATH` | `data/messages.json`     | Файл для `STORAGE=json`                |
| `DATABASE_PATH`  | `data/messenger.db`      | Файл бази для `STORAGE=sqlite`         |

Приклад із SQLite: `STORAGE=sqlite PORT=8080 python3 -m messenger`.

## Сховища даних

- **JSON** — один файл, запис атомарний (тимчасовий файл + `os.replace`). Формат
  повністю сумісний із файлом `messages.json` з TypeScript-версії, тож старі дані можна
  просто підкласти.
- **SQLite** — Python-аналог Cloudflare D1 з оригіналу. Використовує ті самі SQL-міграції
  з `migrations/` (застосовані міграції відстежуються через `PRAGMA user_version`).
  Нові зміни схеми додавай окремими файлами `0002_*.sql`, `0003_*.sql` тощо — вони
  застосуються автоматично під час наступного запуску.

## Структура

```
messenger/
  models.py          # User, Conversation, Message, MessengerData
  errors.py          # MessengerError (з HTTP-статусом)
  service.py         # уся бізнес-логіка та валідація
  server.py          # HTTP API + роздача public/ + заголовки безпеки
  __main__.py        # точка входу: python -m messenger
  storage/
    json_repository.py
    sqlite_repository.py
    validation.py    # перевірка цілісності даних під час завантаження
public/              # фронтенд (HTML/CSS/JS) — без змін
migrations/          # SQL-схема для SQLite
tests/               # тести (unittest)
```

## API

| Метод і шлях                              | Опис                                      |
| ----------------------------------------- | ----------------------------------------- |
| `GET /api/users`                          | Список користувачів                       |
| `POST /api/users`                         | Створити користувача `{username}`         |
| `GET /api/conversations?userId=`          | Розмови користувача                       |
| `POST /api/conversations`                 | Створити розмову `{title, participantIds}`|
| `GET /api/conversations/:id/messages?userId=` | Історія повідомлень (лише учасникам)  |
| `POST /api/conversations/:id/messages`    | Надіслати `{senderId, text}`              |
| `GET /api/search?userId=&q=`              | Пошук у розмовах користувача              |

Обмеження: ім’я — до 30 символів (`a-z A-Z 0-9 . _ -`), назва розмови — до 80,
повідомлення — до 4000, тіло запиту — до 16 КБ.

## Перевірка

```sh
python3 -m unittest discover -s tests -t . -v
```

Тести перевіряють JSON- і SQLite-збереження, групові розмови, валідацію, пошук,
цілісність даних і HTTP API.

**Важливо:** застосунок поки не має паролів чи справжньої автентифікації. Будь-хто з
доступом до сервера може створювати профілі та писати від імені відомих користувачів.
Використовуй його як демо, не для приватного листування чи чутливих даних.
